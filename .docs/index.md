# open-karte

open-karte は、従業員台帳を土台に社内の事実、申請、承認、記録を束ねるセルフホスト基盤である。会社そのものを一つの分類表へ押し込めず、業務能力、共通意味モデル、横断統制を組み合わせて社内事務を表現する。

## 利用者が片付けたいこと

- 社員は、申請、記録更新、検索、予約、目標管理、キャリア申告などの日常手続きを一箇所で済ませる。
- 上長や担当者は、担当する人と組織の状態を把握し、割り当てられた承認、評価、面談、運用作業を行う。
- 管理者は、組織、アカウント、権限、業務定義、証跡を安全に管理する。
- CLI を利用する人と AI は、Web と同じ業務 API を機械可読な形で利用する。

## 製品の境界

対象は社内事務である。従業員、組織、時間、資源、支出、成長、知識、統制に関する事実の登録、更新、検索と、それに伴う申請、承認、証跡、外部連携を扱う。

給与、税、会計、労務、法務に関する重い計算や法的判断は持たず、外部の専門システムまたは専門家へ委ねる。ただし、判断に必要な入力事実、依頼、承認結果、外部結果の参照、連携履歴は製品の対象になり得る。

顧客獲得、販売、製品開発、顧客向け提供、売上管理などのフロントオフィス能力は、会社全体の網羅性を確認するため [[capability-map|機能網羅表]] では分類するが、open-karte の実装対象外とする。

## 体系化の原則

- 業務能力層は、会社が何を達成するかを分類する。
- 共通意味モデル層は、主体、組織関係、時間、資源、金額、文書、手続き、証跡などを一貫して表現する。
- 横断統制層は、認証、認可、職務分離、監査、保持、外部連携をすべての業務へ適用する。
- 人、時間、物、お金、成長の五軸は、排他的なデータ所有区分ではなく、画面、検索、説明に使う複数選択可能な観点とする。
- 実装の有無は、実装済み、部分実装、台帳のみ、未実装、対象外に分け、将来像と現状を混同しない。
- API が業務規則と認可の正本であり、Web と CLI は提供面である。ドメインが存在しても、すべての操作が三つの提供面に揃っているとは限らない。

## 業務知識ベース

open-karte が扱う社内事務手続きの背景知識を、コードとは別に蓄える。AI が CLI で読み書きし、矛盾の検出、知識の追加、案内作成、社内サポートに使うことを想定する。

- 用語の索引は [[glossary|用語集]] とし、制度用語の個別定義は references/terms 配下に置く。
- 手続きの流れは [[notes/README|ノート]] の handbook にまとめる。
- 法令の根拠数値は sources 配下のサマリーに出典付きでまとめる。

ここに置く制度知識は判断の前提であり、給与額や税額の自動計算には使用しない。

## 技術スタック

- Bun は、モノレポと CLI の実行環境に使う。
- Hono は、API と CLI のルーティング基盤に使う。
- Cloudflare Workers と wrangler は、API のランタイムとデプロイに使う。
- Cloudflare D1 と Drizzle ORM は、データ永続化に使う。
- Next.js は、Web の基盤に使う。
- Zod と zod-validator は、入力検証と型生成に使う。
