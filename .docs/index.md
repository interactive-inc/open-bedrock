# open-karte

## ジョブ(顧客が片付けたいこと)

- 社員: 申請の提出や承認、ナレッジ検索、目標管理、キャリア申告などの社内手続きを一箇所で済ませたい
- 上長や管理者: 組織と個人の状態を俯瞰し、承認や評価、1on1の記録を効率よく回したい

## ビジョン

社内の人材データと業務手続きを1つのプラットフォームに集約し、組織を俯瞰する/個人を深く知る/時系列で追うの3視点から扱えるようにする。

## 解決する問題

- 人材データ、申請ワークフロー、[[features|ナレッジ]]、評価、キャリアが別々の仕組みに散らばっている
- 同じ業務を複数のインタフェースから実行する手段がない

## ターゲット

- 社員: 日常の社内手続きを行う一般利用者
- 上長や管理者: 承認、評価、組織把握を担う利用者
- 未確認: 具体的な導入企業像や利用規模はコードから読み取れない

## 原則

- 同じ業務を api と karte コマンドと web の複数インタフェースから実行できるようにする
- Claude などの AI から CLI で呼ばれることを前提に設計する
- 給与・税・労務のような重い計算や法的判定は持たず、外部に委ねる

## やらないこと

- 給与・税・労務の計算や法的判定。これらは外部に委ねる

## 技術スタック

- bun: 理由: モノレポと CLI の実行環境
- Hono: 理由: api と cli の双方で同一のルーティング基盤を使うため
- Cloudflare Workers と wrangler: 理由: api のランタイムとデプロイ手段
- Cloudflare D1 と Drizzle ORM: 理由: api のデータ永続化
- Next.js: 理由: web のフロントエンド基盤
- Zod と zod-validator: 理由: 入力検証と型生成
