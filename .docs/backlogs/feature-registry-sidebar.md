# 機能レジストリとサイドバーの再設計

最終更新: 2026-07-28

## 背景

機能が [[feature-tiers|機能区分]] のどれに属するか、開発中か使用可能かをサイドバーで分かるようにし、管理できるようにしたい。多くの機能は API と UI があるだけで実用水準になく、ユーザ視点でレビューされていない。未成熟な機能を含む全機能を並べることがサイドバーの分類を難しくしている。

## 調査

- サイドバーは web/components/sidebar-nav.tsx の静的配列で構成される。空間タブ（自分・部署・会社・システム）とセクションの二層で、会社タブの人事・労務セクションに 20 項目超が平積みになっている [^1]
- 機能の有効・無効の切替は未実装。schema.ts には存在しない機能フラグテーブルの孤児コメントが残っていた [^2]
- ユーザは区分や職能ではなく用事（休みたい、立て替えた）で探すため、使える機能だけが表示されることが分類の工夫より先に効く

## 対応案

- 案A: JSON ハードコードの機能レジストリを正本にする。1 機能 1 エントリに slug、tier（機能区分）、status（使用可能・開発中・廃止候補）、group（サイドバーのグループ）、ルートを持たせ、サイドバーはレジストリから生成し status が使用可能のものだけ表示する
- 案B: DB テーブルと管理画面で有効・無効を切り替える
- グルーピングの軸（対象 5 軸か職能軸か）は、表示する機能が絞れてから決める。候補は共通セクションと職能軸の組み合わせ
- 経営ダッシュボードは廃止候補とする
- レジストリの group は表示専用とし、API や権限の境界に流用しない（[[product-purpose|製品目的と境界]] の「部署名を永続的な境界にしない」に従う）

## 判断

開発する。案A を採用する。先に全機能の棚卸しレビューを行い、機能ごとにユーザ視点で使用可能・開発中・廃止候補を判定し、その結果を status の初期値にする。

[^1]: 2026-07-28 web/components/sidebar-nav.tsx の実装確認

[^2]: 2026-07-28 api/src/schema.ts。コミット 4c77c07c で孤児コメントを削除
