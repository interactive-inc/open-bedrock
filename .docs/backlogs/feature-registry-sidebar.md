# 機能レジストリとサイドバーの再設計

最終更新: 2026-07-29

## 背景

機能が [[feature-tiers|機能区分]] のどれに属するか、開発中か使用可能かをサイドバーで分かるようにし、管理できるようにしたい。多くの機能は API と UI があるだけで実用水準になく、ユーザ視点でレビューされていない。未成熟な機能を含む全機能を並べることがサイドバーの分類を難しくしている。

## 現状

- web/lib/feature/feature-registry.ts が機能とサイドバー経路の正本である。57 機能に slug、tier、status、group、アイコン、90 表示経路を持つ
- サイドバーは自分・部署・会社・システムの空間タブの内側を、概要、人と組織、時間と予定、申請と手続き、成長と評価、情報共有、資産と施設、経営と統制、システム運用、個人設定で分類する
- 使用可能は通常色、開発中は琥珀色のアイコンで表示し、廃止候補は表示しない。色だけに依存しないよう、サイドバー上部に開発中の凡例を表示する
- 初期値は使用可能 11、開発中 45、廃止候補 1 とする。ユーザ視点の利用レビューが完了していない機能は開発中に置く
- 経営ダッシュボードは廃止候補とする
- group は表示専用であり、API や権限の境界に流用しない（[[product-purpose|製品目的と境界]] の「部署名を永続的な境界にしない」に従う）
- 権限による項目の非表示は継続する。機能の有効と無効を切り替える runtime 設定は未実装である

## 判断

DB ではなく静的な機能レジストリを採用する。アイコンと権限条件をコンパイル時に検査するため、JSON ではなく TypeScript の定数とする。機能はユーザ視点の利用レビューが完了した場合にのみ、status を使用可能へ変更する。
