# 従業員台帳 CRUD+検索

最終更新: 2026-05-31

優先度: 最優先(MVP)。他の全バックログがこれに依存する。

---

## 背景

[[index|open-karte]]の全ワークフローは人を参照して成立する。[[time-attendance-leave|勤怠・休暇]]も[[asset-lending|備品貸与]]も[[expense-request|経費]]も「誰の」記録かを従業員に紐づける。その参照元となる[[features|従業員台帳]]が無ければ、どの領域も着手できない。

解く課題: 運用担当が、社内の人の事実(氏名・所属・在籍状況など)を一箇所で登録・更新・検索できない。人を指す情報が各手続きに散らばると、同一人物の名寄せができず記録が信頼できなくなる。

## 調査

- 既存コードは存在しない。実装はゼロからになる [^1]
- AGENTS.md が「従業員台帳を土台に」と明記しており、台帳が依存の根である方針は確定している [^1]

## 対応案

- 最小の形(MVP): 従業員の登録・取得・更新・退職(在籍状況の変更)と、キーワード・部署・在籍状況での検索を api に持たせ、karte コマンドから操作できるようにする。web はこの後に回す
- 受け入れ条件の骨子: 従業員を登録すると一覧と詳細で取得できる / 氏名や所属を更新でき更新後の値が取得できる / 退職にすると在籍状況で絞り込んで除外できる / キーワードと部署で検索すると該当者だけが返る / 公開リポジトリのため実在しうる氏名やメールを含めない(サンプルは汎用値)
- 案B(拡張): 部署マスタやレポートラインも同時に持つ。ただし MVP では従業員の基本属性に絞り、組織構造は次段に分ける
