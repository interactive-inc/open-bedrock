# 勤怠・休暇申請

最終更新: 2026-05-31

優先度: 中。時間領域の中核。台帳と申請基盤の後。

---

## 背景

時間領域(人の働く時間)の事実を記録し、休暇を申請できるようにする。出退勤や休暇が紙やバラバラのツールにあると、本人も上長も現在の状態を把握できない。

解く課題: 社員が出退勤を記録できず、休暇の申請と残数の把握ができない。上長は休暇申請を一覧で見て承認できない。

依存: 記録の主体に[[employee-directory|従業員台帳]]、休暇の承認に[[approval-workflow|申請ワークフロー基盤]]を必須とする。

## 調査

- 既存コードは存在しない [^1]
- 休暇の残数計算は単純な記録の積み上げに留め、給与・労務の計算には踏み込まない方針([[index|やらないこと]]) [^1]

## 対応案

- 最小の形(MVP): 出退勤の記録と自分の勤怠の確認、休暇の申請と残数の確認、休暇申請の承認/却下を提供する。残数は付与と消化の差し引きという単純な記録に留める
- 受け入れ条件の骨子: 出勤と退勤を記録すると自分の勤怠として確認できる / 休暇を申請すると[[approval-workflow|申請ワークフロー基盤]]に乗り承認待ちになる / 承認されると残数が減る / 残数を確認できる / 法的判定や賃金計算は行わない
- 案B(打刻の自動化): 打刻のリマインドや自動集計を持つ。MVP では手動記録に絞る
