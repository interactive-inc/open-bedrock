# バックログ

[[index|open-karte]]の初期バックログ。全5件、すべて判断は未定で実コードはゼロから着手する。価値と依存関係の順に並べると、土台となる[[employee-directory|従業員台帳]]を根に、申請の共通基盤、そして時間・物・お金の各領域が積み上がる構造になる。最初の MVP は従業員台帳 CRUD+検索を推す。

## 基盤

[[employee-directory|従業員台帳 CRUD+検索]]が最優先である [^1]。全ワークフローが人を参照して成立するため、台帳が無ければ他のどの領域も着手できない依存の根になる。MVP は従業員の登録・更新・退職・検索を api と karte コマンドで提供し、web は後段に回す。

その上に[[approval-workflow|申請ワークフロー基盤]]を置く [^2]。時間・物・お金の申請はいずれも「申請し、承認し、記録する」同じ形をしており、領域ごとに作り直すと整合が崩れる。MVP は汎用の申請エンティティと単一承認者の承認導線に絞る。

## 時間

[[time-attendance-leave|勤怠・休暇申請]]で、出退勤の記録と休暇の申請・残数確認・承認を扱う [^3]。残数は付与と消化の差し引きという単純な記録に留め、賃金計算や法的判定には踏み込まない。

## 物

[[asset-lending|備品・貸与管理]]で、備品の在庫と貸出・返却を記録し、誰が何を借りているかを追えるようにする [^4]。会計上の資産管理(減価償却など)は持たない。

## お金

[[expense-request|経費申請]]で、経費の申請と精算状態を記録し、承認待ちの確認と承認を扱う [^5]。税計算や会計仕訳は境界の外として外部に委ねる。
