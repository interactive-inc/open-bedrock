# 申請ワークフロー基盤

最終更新: 2026-05-31

優先度: 高。各領域の申請(時間・物・お金・成長)が共通で使う土台。

---

## 背景

[[time-attendance-leave|休暇]]も[[expense-request|経費]]も[[asset-lending|備品貸与]]も、本質は「誰かが申請し、誰かが承認し、結果を記録する」同じ形をしている。領域ごとに別々の申請の仕組みを作ると、承認導線や状態管理が重複し、整合が取れなくなる。

解く課題: 社員が出した申請と上長の承認結果が、領域をまたいで一貫した形で記録・確認できない。承認者は領域ごとに別の画面を見に行く羽目になる。

依存: 申請者と承認者の特定に[[employee-directory|従業員台帳]]を必須とする。

## 調査

- 既存コードは存在しない [^1]
- 各領域の申請は状態遷移(申請中・承認・却下)とコメントという共通要素を持つと整理できる [^1]

## 対応案

- 最小の形(MVP): 領域を問わず使える汎用の申請エンティティを持つ。申請の提出、自分の申請一覧、自分宛の承認待ち一覧、承認/却下(コメント付き)を api と karte コマンドで提供する。承認ルートは単一承認者から始める
- 受け入れ条件の骨子: 申請を提出すると申請中になり自分の申請一覧に出る / 承認者の承認待ち一覧に出る / 承認すると承認済みに、却下すると却下済みに状態が遷移する / 却下時にコメントを残せる / 申請者と承認者は[[employee-directory|従業員台帳]]の従業員として特定される
- 案B(多段承認): 複数段の承認ルートを最初から持つ。ただし MVP では単一承認者に絞り、多段は需要が出てから
