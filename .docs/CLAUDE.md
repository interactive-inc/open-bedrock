# 文書編集規則

- 仕様本文には製品、業務、実装の事実、制約、不変条件だけを書く
- 文書の目的、読者、読み方、文書種別、規範性、正本性を本文に書かない
- `仕様書`、`仕様正本`、`補助仕様`、`実装写像`、`根拠記録`、`非規範記録`、`manifest` を分類語として使用しない
- H1 は対象となる製品、概念、能力または実装面の名前にする
- 要件は条件、主体、対象、許可または禁止される操作、失敗時の結果を明示する
- 未実装の概念を実装済みと表現しない
- 例から要件を追加推定できる書き方をしない
- route、table、column、入出力型はコード、migration、生成型と照合する
- 実装計画、判断履歴、作業手順、一般例、外部調査、移行記録を `.docs` に置かない
- 同じ制約を複数ファイルへ複製せず、定義元へリンクする
- Markdown は `../.claude/rules/md.md` に従う
