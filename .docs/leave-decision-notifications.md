# 休暇判断の通知

休暇の承認・却下はSystemに判断を記録し、最終結果の業務反映で休暇状態、残数変更、監査、通知予約を同じtransactionへ保存する。通知予約を保存できなければ業務反映を確定せず、判断済み・確定待ちとして再試行する。反映後の配信失敗は結果を取り消さずSystemのJobとして再送する。

通知予約は判断の監査ID、申請ID、受信する従業員ID、結果、判断日時を固定する。申請理由と承認者のコメントは通知へ複製しない。予約内容の更新・削除と同一判断の重複予約をDBで拒否する。

## 配送と権限

定期実行は`LEAVE_NOTIFICATION_SERVICE_ACCOUNT_ID`に明示したServiceで配送する。未設定の場合と休暇Appが無効の場合は配送しない。Serviceには`batch:execute`、`employee:read`、`leave:read:all`が必要である。

受信先は配信時点の会社営業日に有効な従業員とAccountの対応から解決する。対応を一意に決められない場合、Accountが停止・ロック・終了している場合、Serviceの権限が不足する場合は配信しない。保存時にも会社の履歴と権限、受信Accountの状態を検査する。

通知とJobの完了を同じtransactionで保存する。並行実行と再実行で同じ判断の通知を重複保存しない。保存失敗は再送待ちに戻し、試行上限に達した場合はdead letterへ残す。過去の判断から通知予約を自動生成しない。
