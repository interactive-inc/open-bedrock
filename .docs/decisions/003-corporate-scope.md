# 事業ドメインは扱わず、管理部門の業務に限定する

## 状況

基盤を「あらゆる業務システムのパターン網羅」へ広げる構想があり、顧客管理(CRM)や在庫管理も拡張候補に挙がっていた。全体地図を描き切るにあたり、どこまでを守備範囲にするかの線引きが必要になった。

## 判断

open-karte は会社の管理部門(総務・人事・情シス・経営管理)の業務に限定する。販売・顧客管理・在庫・製造・調達など、事業そのものの運営(事業ドメイン)は扱わない。ただし取引先台帳・契約記録・[[hansha-check|反社チェック]]のような、管理部門が担う対外業務は対象に含める。

## 理由

- 管理部門の業務はどの会社でもほぼ同形であり、基盤の普遍性を保てる。事業ドメインは業種ごとに形が違い、作り込むほど特定業種向けの業務システムになって基盤の焦点がぼける
- 事業ドメインは専門 SaaS の競争が激しく、そこでは戦わない
- 基本パターン(台帳・申請承認・記録・割当・集計)の設計自体は事業ドメインにも通用する。必要になったら、同じ設計で別プロダクトとして作れば良い

## 結果

- 全体地図([[index|index]])で在庫管理・購買(調達)・顧客管理(CRM)・商談管理を「しない」に分類した
- 対外領域は取引先台帳・契約記録・反社チェックに絞った
