# お金は事実の記録まで扱い、壊れると実害が出る計算と実行は持たない

## 状況

当初の方針は「給与・税・労務のような重い計算や法的判定は持たない」だった。基盤を総務業務の全域に広げるにあたり、経費・サンクスポイント・給与改定のような金額を含むデータをどこまで扱うかの線引きが必要になった。migration には payslips と salary_revisions のテーブルが存在する一方で API は未実装であり、位置づけが曖昧だった。

## 判断

線引きの基準を「金額かどうか」ではなく「壊れたときのダメージ」に置く。

- 扱う: 金額を含む事実の記録・更新・検索と、それにまつわる申請承認ワークフロー（経費の申請、[[keihi-seisan|経費精算]]の記録、ポイントの残高、給与改定の履歴など）
- 扱わない: 誤りが金銭損害や法令違反に直結する計算・判定・実行。給与計算、税額計算、仕訳・会計処理、支払の実行、労務・税務の法的判定はすべて外部の専門サービスに委ねる

## 理由

- 総務の業務の多くは金額を含む記録であり、金額を一律に排除すると基盤として成立しない
- 記録に徹すれば、誤りがあっても「記録の修正」で回復できる。計算や支払の誤りは回復できない実害になる
- 計算・支払・法的判定は専門 SaaS の独壇場であり、そこで競争しない

## 結果

- payslips と salary_revisions は給与改定の事実記録のテーブルとして存続してよい。将来 API 化する場合も計算機能は持たない
- 経費とサンクスポイントは現行どおり（申請・承認・残高の記録まで）
- [[index|index]] の「やらないこと」をこの基準で書き直した
