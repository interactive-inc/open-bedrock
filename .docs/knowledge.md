# 社内知識

知識記事は業務contextの `knowledge` が所有する。共有する本文を残し、過去の版を根拠として参照できる。規程の施行や人間の承認済み判断とは区別する。

## 作成と変更

認証済みの在籍者が記事を作成し、作成者本人が更新または取下げる。保存時にはSystemの認証とCompanyの職員対応・在籍資格を再検査する。資格の失効、会社情報の変更、会社の日付境界をまたいだ保存は拒否する。

作成・更新・取下げは理由と `Idempotency-Key` を必要とする。更新・取下げは確認した版を引用符付きの `If-Match` に指定する。版が異なる場合は競合として拒否し、最新版へ自動的に読み替えない。

同じ主体が同じキー・同じ操作内容を再送した場合は、現在の資格を再検査したうえで元の結果を返す。同じキーを別の内容に使うことはできない。

本文の現在状態、変更不能な改訂履歴、System監査を同じtransactionで保存する。いずれかの保存に失敗した場合は全体を取り消す。

## 取下げと履歴

取下げは本文を物理削除しない。通常の検索結果から除外し、詳細と改訂履歴には取下げ状態を残す。取下げ後の本文更新は拒否する。

記事と履歴は同じ認証済みの共有範囲で閲覧できる。履歴は版の降順で本文、状態、理由、記録時刻、操作したAccountを返す。記録したAccountがあることだけで、人間による承認を表現しない。

既存記事は現在残っている本文を初版として保持する。過去の編集者・編集時刻は推定せず、既存記録由来であることと履歴への記録時刻を区別する。

## CLI

`knowledge-articles get` は本文と現在の版・状態を表示する。`knowledge-articles history` は過去の本文と記録理由をページ単位で返す。作成は `add`、更新は `edit`、取下げは `withdraw` を使う。

書き込みには `--reason` と `--idempotency-key`、更新・取下げには確認済みの `--revision` も必要とする。通信失敗後に同じ操作を再送するときは同じキーを使う。
