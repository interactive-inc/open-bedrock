# サービス利用台帳

`software-license` は、会社が利用するサービスの契約・プランと、従業員への割当を記録する。System の認証・操作権限・監査と、Company の従業員・在籍履歴だけに依存する。

## 契約と利用者

一つの契約・プランを一つのライセンス記録として持つ。同じサービスに複数の契約がある場合は、それぞれの記録を作る。サービス名、プラン名、ベンダー、契約座席数、更新期限、管理担当、備考、契約状態、版を保存する。

利用者の割当は、契約と従業員のID、外部サービス内のアカウントを識別する参照、割当時のサービス名・プラン名、記録者、記録日時、理由を保存する。割当後の契約名変更で過去の割当内容を変更しない。利用者の表示名は現在のCompanyから取得する。

割当と解除は社内台帳の記録である。外部サービスでのアカウント作成、権限付与、無効化、実際の利用を確認したことを意味しない。パスワード、APIキー、カード情報をアカウント参照や備考へ保存しない。支払・経費精算・カード取引を実行しない。

## 操作資格と整合性

閲覧には `license:read:all`、記録には `license:manage` を要求する。Systemの管理権限も技術的操作を許可する。書込時には、現在の在籍従業員に対応するHumanであることを確認する。新しい割当先と指定された管理担当も現在の在籍従業員に限る。Agentは閲覧権限に従って参照できる。Agentによる直接記録と人間への判断依頼の接続は未実装である。

会社の対応・在籍、Account、Principal、権限の付与元を保存のtransactionでも再検査する。確認後に変更があった場合は保存を拒否する。技術的な管理権限を、サービス導入や支出に対する承認として扱わない。

同じ契約内では、一人の従業員に有効な割当を重複させない。アカウント参照を指定した場合は、その参照の重複も拒否する。契約座席数が未設定の場合は上限を判定しない。座席数を指定した契約では、同時登録を含めて上限を超える割当を拒否する。

有効な割当が残る契約は解約できず、座席数を現在の割当数より減らせない。解除後は座席を再利用できる。退職者への新規割当を拒否する一方、過去の割当は在籍する記録担当者が解除できる。

解除には記録者、記録日時、理由を追記する。割当より前の解除日時、割当履歴の削除、確定した解除の上書きを拒否する。誤った割当は理由を付けて解除し、必要に応じて新しいIDで登録する。割当・解除とSystemの監査は一括保存し、監査の保存に失敗した場合は割当の変更も取り消す。

契約の変更前後と記録者は変更履歴へ一括保存する。導入前の変更履歴や記録者を推測して補完しない。初回変更時には、変更直前の契約内容も保存する。

## API

API rootからの相対パスを次に示す。

- `GET /software-license/software-licenses`: 契約・プラン一覧。
- `POST /software-license/software-licenses`: 契約・プラン登録。`name` は必須。`plan_name`、`vendor`、`category`、`seats`、`renewal_deadline`、`owner_employee_id`、`note` を指定できる。
- `GET /software-license/software-licenses/:id`: 契約・プランと `ETag` の参照。
- `PUT /software-license/software-licenses/:id`: 契約内容の更新。`plan_name` を省略した場合は既存のプラン名を保持する。その他の省略可能属性は未設定へ更新する。
- `POST /software-license/software-licenses/:id/cancel`: 契約の解約状態を記録する。外部サービスへの解約依頼は行わない。
- `GET /software-license/software-licenses/:id/history`: 契約内容の変更履歴。
- `POST /software-license/software-licenses/:id/assignments`: `id`、`employee_id`、`reason` と、任意の `account_reference` を指定して割当を記録する。`id` は呼出元が発行するUUIDとする。
- `GET /software-license/software-licenses/assignments`: 割当と解除履歴。`license_id`、`employee_id`、`state=assigned|released` で絞り込める。`limit` は1から100、`offset` は0から100000を指定できる。`has_more` で続きを判定する。
- `POST /software-license/software-licenses/assignments/:assignmentId/release`: `reason` を指定して解除を記録する。

契約登録では `Idempotency-Key` を指定して再送する。同じ記録者・キー・登録内容なら最初の確定結果を返し、内容が違えば409を返す。キーを省略した従来の呼出しでは、登録の重複を検出しない。

契約更新・解約では、参照した `ETag` を `If-Match` に指定する。表示後に版が変わっていれば409を返す。ヘッダーを省略した従来の呼出しも、読み取りから保存までの同時更新は拒否するが、呼出元が以前表示した版は検査できない。

割当の再送では同じUUIDと同じ入力を使う。同じ記録者による同じ割当は200、新規記録は201を返す。別内容によるIDの再利用は409を返す。解除の再送は、記録者と理由が一致する場合に元の解除結果を返す。再送で履歴や監査を重複作成しない。

`SOFTWARE_LICENSE_ENABLED=false` を設定すると全ての台帳APIを404で停止する。未設定または `true` の場合に有効とし、その他の設定値でも停止する。製品側の機能無効化がある場合は、その制限も適用する。

## 未接続の機能

サービス定義の独立した名寄せ、外部サービスからの利用実績の取得、契約更新通知、導入前の相談・承認、外部稟議との対応、AIへの記録委任は未実装である。利用者割当のWeb画面とCLI専用コマンドも未実装で、割当と解除はAPIを利用する。
