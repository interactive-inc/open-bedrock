# 企業モデルと認可を設計するための参照標準

この文書は、open-karte の会社モデルで参照する外部標準と採用目的を記録する。標準の語彙と設計観点を社内事務へ合わせて利用し、各標準への製品仕様上の直接準拠、認証取得、完全実装は主張しない。

## 参照するときの原則

- 公式発行元の文書を参照し、解説記事を規範の代わりにしない
- 概念を借りるときは、open-karte での意味、対象範囲、不変条件を [[company-model|会社モデル]] に定義する
- 標準のクラス名、交換形式、図式、適合要件を実装済みと推定しない
- 標準の更新を自動採用せず、モデルの意味が変わる場合は決定記録を追加する
- 法令、社内規程、契約が定める要件を外部標準だけで置き換えない

## 組織構造の標準語彙

[W3C Organization Ontology](https://www.w3.org/TR/vocab-org/) は、組織、組織単位、構成関係、所属、役割、職位、報告関係、拠点、組織変更を表すための中核語彙を定義する。

採用目的は、組織、組織単位、所属、業務上の役割、職位、拠点の意味と関係を揃えることである。W3C ORG の `Organization`、`OrganizationalUnit`、`Membership`、`Role`、`Post`、`Site` を、open-karte の `Organization`、`OrgUnit`、`Membership`、`OrgRole`、`Position`、`Site` へ対応づける。

open-karte の `SystemRole` と `Permission` は IAM の操作能力を表す製品概念であり、W3C ORG の `Role` へ対応づけない。組織上の責任とシステム権限を別概念として保ち、認可判定で組み合わせる。

RDF、OWL、名前空間、リンクトデータ公開は採用条件にしない。open-karte は TypeScript とリレーショナルスキーマで概念を実装でき、W3C ORG 互換の RDF を出力するとは主張しない。

## 来歴の標準語彙

[W3C PROV-O](https://www.w3.org/TR/prov-o/) は、`Entity`、`Activity`、`Agent` と、生成、利用、派生、帰属、関連、代理の関係を使って来歴を表現する。

採用目的は、申請、判断、文書、外部取込、訂正の出所を共通の問いで追跡することである。何が、どの活動で、何を使用して、誰またはどのシステムの責任で生成されたかを監査と説明に利用する。

PROV-O の全クラス、OWL 制約、RDF 交換形式は実装要件にしない。既存の監査ログだけで PROV-O 適合を満たすとはみなさず、領域に必要な来歴を open-karte の型と保存方式で表す。

## 属性ベースアクセス制御

[NIST SP 800-162](https://csrc.nist.gov/pubs/sp/800/162/upd2/final) は、属性ベースアクセス制御を、主体、対象、操作、環境の属性と方針を評価する認可方式として説明する。

採用目的は、ロールだけに依存しない認可判断を設計することである。本人所有、組織関係、対象状態、操作、委任期間、アクセス時の環境を明示し、一覧、詳細、集計、出力へ同じ情報境界を適用する。

既存のロールベース制御は廃止しない。ロールを主体属性または関係属性の一つとして組み込み、NIST の連邦機関向け運用要件、評価、認証への適合は主張しない。

## 業務プロセス表記

[OMG Business Process Model and Notation 2.0.2](https://www.omg.org/spec/BPMN/2.0.2) は、業務プロセスのイベント、活動、分岐、参加者、メッセージ、順序を共有図式で表す。

採用目的は、手続き定義の開始、タスク、待機、分岐、合流、終了、参加者間の受け渡しを一貫した語彙で説明することである。利用者向けの業務説明と、実装する状態遷移のレビューを接続するために参照する。

BPMN 実行エンジン、XML 交換、図の取込と出力、適合クラスへの準拠は実装要件にしない。すべてのケースを事前定義できるフローとして扱わず、個別判断や外部応答を待つケースには領域固有の状態とタスクを許す。

## 業務アーキテクチャの中核モデル

[OMG Business Architecture Core Metamodel 1.0](https://www.omg.org/spec/BACM/1.0) は、業務能力を中心に、価値、成果、組織、価値の流れなどの事業アーキテクチャ概念を関連づける正式仕様である。

採用目的は、業務能力を組織、プロセス、システムから独立した安定単位として扱うことである。能力カタログの包含関係、能力を実現する手続き、責任組織、期待成果を分けて記述する観点に利用する。

BACM の全メタモデル、交換形式、適合要件、価値モデルを実装しない。open-karte の業務能力カタログが BACM 準拠モデルであるとは主張せず、社内事務の範囲に必要な概念だけを採用する。

## 記録管理の原則

[ISO 15489-1:2016](https://www.iso.org/standard/62542.html) は、記録、記録メタデータ、記録システム、方針、責任、統制、記録の作成、捕捉、管理に関する概念と原則を定める。

採用目的は、申請、判断、証拠、生成文書、監査イベントを、後から業務活動を説明できる記録として管理することである。作成主体、文脈、版、完全性、利用可能性、機密区分、保持、廃棄の設計観点に利用する。

保持期間や廃棄可否は、ISO 15489-1 だけから決定しない。適用法令、契約、社内規程、法的保全の外部判断を入力とし、ISO 認証または完全適合は主張しない。

## プロセス分類の枠組み

[APQC Process Classification Framework](https://www.apqc.org/process-frameworks) は、組織が行う主要なプロセスを階層的に分類し、共通言語、比較、プロセス管理へ利用する枠組みである。

採用目的は、open-karte の能力カタログと社内事務領域に大きな漏れがないかを点検することである。能力名や手続き名の候補、上位と下位の粒度、領域間の重複をレビューする入力に使う。

APQC の分類をそのまま製品メニューへ複製せず、公開範囲と利用条件を確認する。ベンチマーク互換、分類番号の互換、全プロセスの実装、APQC による認定は主張しない。

## 標準間の役割分担

W3C ORG は組織構造、W3C PROV-O は来歴、NIST SP 800-162 は認可判断、OMG BPMN は手続きの流れ、OMG BACM は業務能力、ISO 15489-1 は記録管理、APQC PCF は業務領域の網羅性を点検する。

同じ概念名が複数標準に現れる場合は、open-karte の定義と不変条件を優先する。外部との交換仕様を追加する場合に限り、対象標準の適合要件と語彙への写像を別の決定記録で定める。
