# 機能一覧

業務機能の中心は API が提供し、karte コマンドと Web が利用する。提供面は操作ごとに異なり、同じドメインが存在しても API、Web、CLI の操作が同じとは限らない。機能の実装は `api/src/interface` と `api/src/app.ts` を正とし、会社業務全体に対する現在の範囲は [[capability-map|機能網羅表]] を参照する。

勤怠、評価、シフト、研修、通知を含む主要ドメインには web 画面がある。web 画面の一覧は [[sitemap|サイトマップ]]、主要導線は [[user-flows|ユーザーフロー]] を参照する。給与明細、給与改定、年末調整は台帳スキーマだけがあり、API、Web、CLI はない。台帳の存在はロードマップへの採用を意味せず、採用済みの項目は [[backlogs/README|バックログ]] で区別する。

## 認証

- メールアドレスとパスワードでログインし、トークンを取得する
- ログイン中の自分の情報を表示する

## 社員と組織

- 社員を検索する(キーワード、部署、在籍状況で絞り込み)
- 人物台帳、入社日付き人事発令、初期アカウントを一括登録し、人物台帳の氏名を編集する
- 入社、配属、異動、役職変更、上司変更、休復職、退職、再入社を有効日付き人事発令として記録する
- 従業員詳細で現在の人事状態と確定済みまたは予定済みの人材タイムラインを確認する
- マネージャーは組織範囲内の人事変更を申請し、人事権限を持つ担当者は直接確定または訂正する
- 退職済み従業員を履歴保持のままアーカイブし、アカウントを停止する
- 一般業務の社員選択では、在籍中社員のコード、氏名、部署、役職だけを安全な社内ディレクトリから参照する
- 組織ツリーやレポートライン、部署メンバーを確認する
- 部署を作成、編集、アーカイブする。部署責任者と上司は人事発令からだけ変更する

## 申請ワークフロー

- 申請テンプレートの一覧と詳細を確認する
- テンプレートを指定して申請を提出する
- 自分宛の承認待ち一覧と、自分が出した申請を確認する
- 申請を承認または却下する(コメント付き)
- 全社の申請を横断で確認する(`application:read:all` を持つロール)
- テンプレートごとに、組織上の直属上司・部門責任者・上位管理職、IAM ロール、従業員指定を組み合わせた多段承認を定義する
- 申請内容と申請者属性による条件分岐、全員承認、必要人数、期限、期限後の承認者、却下または差戻しを設定する
- 差戻し後は監査履歴を残した新しいラウンドとして再申請する
- 期間とテンプレートを限定して代理承認を設定する

## 勤怠と休暇

- 出退勤を打刻し、自分の勤怠と月次サマリを確認する
- 休暇を申請し、残数を確認する
- 休暇を承認または却下する

## 経費

- 経費を申請し、自分の経費を確認する
- 自分宛の承認待ちを確認し、承認または却下する

## 予算

- 部署と会計期間ごとの予算を登録し、金額やメモを修正する
- 予算の詳細で、承認済み経費による消化額と残額を確認する
- 会計期間を指定し、部署ごとの予算・消化額・残額を横断で確認する
- 予算は記録と集計の閲覧に閉じ、承認制御や自動締めのような制御は持たない

## ナレッジ

- ナレッジを検索する(キーワード、カテゴリで絞り込み)
- ナレッジの詳細を確認する
- ナレッジを作成、編集、削除する

## 会議室と備品

- 会議室の空き状況を確認し、予約する
- 備品を登録し、貸出と返却を記録する
- 備品を廃棄済みにする(理由と日付を記録。貸出中は廃棄不可、廃棄済みは貸出不可)
- 現在貸出中の備品を保有者ごとに横断で確認する(管理者向け)
- 棚卸しを開始し、対象備品の現物確認(確認者と所在メモ)を記録して締める

## スキルと目標

- スキルの一覧を確認し、自分のスキルを登録または更新する
- 目標を作成し、自己評価、上長評価、最終評価を登録する

## 個別面談とアンケート

- 1on1の履歴を確認し、記録を作成する
- オープン中のアンケートに回答し、集計を確認する

## 感謝(サンクス)

- 同僚へ感謝メッセージを送る
- 自分の月次の贈与原資(残ポイント)と受け取った感謝を確認する
- 交換カタログの報酬一覧を確認し、ポイントと引き換えに交換を申請する
- 報酬カタログを登録、編集する(管理者)
- 交換申請の承認待ちを確認し、承認または却下する

## キャリア

- 自分のキャリアシートを確認し、更新する
- 社内公募の一覧を確認し、応募する

## オンボーディング

- オンボーディングのテンプレートを管理し、社員に割り当てる
- 入社と退職の人事発令に対応するテンプレートを設定し、冪等なバッチでタスクを自動展開する
- 自分のタスクを確認し、完了にする
- 閲覧担当者は社員別の進行状況を確認し、管理権限がない場合は割り当てやテンプレート変更を行わない

## 評価

- 評価サイクルを作成し、開始と締切を切り替える
- 評価フォームを提出し、結果を確認する
- サイクル開始時に組織図から自己、直属上司、同僚、部下の評価フォームを重複なく自動作成する
- 評価結果はサイクル運営者、終了後の本人、組織上の上司だけが閲覧する

## シフト

- シフトパターンと割当を作成し、公開する
- シフト交代を申請し、申請当事者でない管理者が承認する

## 研修

- 研修コースを作成し、一覧と詳細を確認する
- 研修に登録し、受講を完了にする

## 通知

- 自分宛の通知と未読数を確認する
- 通知を既読にする(個別、一括)
- 宛先を指定して通知を送る(`notification:send` を持つロール)

## 労務・ライフイベント手続き

事実の記録と申出のワークフローのみを扱い、給付額や税額の計算、法的判定は持たない。

- 出張の行き先、期間、目的、概算費用、専用状態を記録し、本人が確認、編集、取り消す。承認 `inbox` と決裁操作はなく、汎用申請ワークフローとは接続していない
- 貸与品の品名、利用期間、用途、専用状態を記録し、本人が予約、編集、取り消す。備品台帳、在庫確保、承認処理とは接続していない
- 退職予定日、最終出勤日、理由、専用状態を記録し、本人が申し出、編集、取り消す。管理担当者の受付と書類交付の操作はない
- ライフイベント(結婚、出産、転居、忌引、扶養変更など)を本人が届け出て、編集、取り消す
- 産休、育休、介護休業の種別と期間を本人が申し出て、編集、取り消す。給付計算と法的判定は行わない
- 在職、就労、退職などの証明書発行を本人が依頼し、編集、取り消す。文書生成、管理担当者の処理、電子交付は行わない
- 取引先の反社チェックを申請し、申請者本人ではない管理担当者が確認結果を記録する

## アカウントとロール管理

- API と Web では、従業員に紐づくアカウントの状態とパスワード再設定を管理する(`account:manage` を持つロール)
- API と Web では、アカウントへのロール割り当てと剥奪を管理する(`iam:assign_roles` を持つロール)
- API と Web では、ロールと権限の一覧を確認し、ロールを作成、編集、削除する(`iam:manage_roles` を持つロール)
- CLI の `karte accounts` と `karte roles` は一覧取得だけを行い、管理操作は行わない
- 自分が持つ権限の範囲でのみロールに権限を割り当てる

## 個人設定

- Web で表示テーマや表示言語を変更する。API、CLI、Schema には同期しない

## ダッシュボードとバッチ

- ダッシュボードの集計を表示する
- バッチの状況を表示する
