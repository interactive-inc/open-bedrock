# 実装機能

業務機能は API が保持し、CLI と Web は操作面として利用する。API、Web、CLI の提供範囲は一致を前提としない。

実装状態は `api/src/interface`、`api/src/app.ts`、`cli/app`、`web/app`、migration、test と一致させる。schema だけが存在する給与明細と年末調整は実装済みと扱わず、roadmap 採用も意味しない。

## 認証

- メールアドレスとパスワードでログインし、アクセストークンとリフレッシュトークンを取得する
- リフレッシュトークンでアクセストークンを再発行する(ローテーション)
- ログイン中の自分の情報(権限とロールを含む)を表示する
- デプロイ直後に初期 ROOT アカウント(従業員、アカウント、パスワード identity、admin ロール)を 1 度だけ作成する。`BOOTSTRAP_TOKEN` を設定した環境でのみ有効で、トークンが一致し、かつ既存アカウントが 0 件のときに成立する。トークン未設定なら機能自体を提供せず(404)、トークン不一致は拒否し(401)、既にアカウントが存在すれば拒否する(409)。パスワードは複雑性ポリシーを満たす必要がある

## 個人と対応の集約

- 本人が対応すべき申請・承認・判定を受信箱ハブに種類別で集約する。申請、経費、休暇、稟議、シフト交代、サンクス交換、反社チェック判定の各受信箱へ導線を出し、件数 API を持つ種類は未処理件数を表示する。表示する種類は本人の permission で絞る
- マイページで本人の基本情報と、今日の勤怠、休暇残、直近の申請を要約し、各 `/my` リソースへの導線を出す

## ロールとアカウント管理

権限の考え方は [ロールと権限](./roles-and-permissions.md) を参照する。

- 権限を選んでロールを作成、編集、削除する(動的ロール)
- アカウントにロールを割り当て、剥奪する
- アカウントの停止、再開、パスワードリセットを行う
- 権限カタログを一覧する

## 情シスの台帳

- ライセンス・SaaS の台帳(座席数・更新期限・管理者)を管理する(`license:manage` / `license:read:all`)
- インシデント(障害・事故)の発生と解消を記録する(`it_incident:manage` / `it_incident:read:all`)

## 社員と組織

- 社員を検索する(キーワード、部署、在籍状況で絞り込み)
- 人物台帳、入社日付き人事発令、初期アカウントを一括登録し、人物台帳の氏名を編集する
- 入社、配属、異動、役職変更、上司変更、休復職、退職、再入社を有効日付き人事発令として記録する
- 従業員詳細で現在の人事状態と確定済みまたは予定済みの人材タイムラインを確認する
- マネージャーは組織範囲内の人事変更を申請し、人事権限を持つ担当者は直接確定または訂正する
- 退職済み従業員を履歴保持のままアーカイブし、アカウントを停止する
- 一般業務の社員選択では、在籍中社員のコード、氏名、部署、役職だけを安全な社内ディレクトリから参照する
- 組織ツリーやレポートライン、部署メンバーを確認する
- 部署詳細ハブで、部署名、コード、責任者のヘッダを共有する。ハブの入口はメンバー一覧へリダイレクトし、概要ページは持たない
- サイドバーの部署タブは、タブ直下の部署セレクタ(自分の所属部署のみ。他部署は組織図から辿る)で対象部署を切り替え、マイチームと代理承認を最上部に置き、選択部署のメンバー・目標・勤怠・休暇へ直接移動する(所属は GET /me/departments)。組織図は会社タブに置く
- 部署ハブで、部署スコープの目標・勤怠・休暇を一覧する(`scope=department`。全社権限か、本人が所属する部署への `:department` 権限で閲覧できる。所属しない部署への `:department` は拒否する)
- 部署メンバー画面から、この部署への配属(主配属・兼務)を人事発令として登録する(`employee:lifecycle:apply`)
- マイチームで直属部下の一覧(GET /me/reports)を確認し、配下スコープの勤怠、休暇、目標を文脈導線として埋め込む。各節は対応するスコープ権限(`attendance:read:reports`、`leave:read:reports`、`goal:read:reports`)を持つ場合のみ表示する
- 部署を作成、編集、アーカイブする。部署責任者と上司は人事発令からだけ変更する
- 等級マスタを管理し、社員への等級割当を履歴として記録する(閲覧は本人・配下・全社のスコープ権限)
- 役職マスタを管理し(`position:manage`)、従業員登録と人事発令の役職はマスタの code から選ぶ。マスタに無い code は 422 で拒否し、役職なしは許可する。従業員が現に使う役職名の削除は 409 で拒否する。役職の期間付き履歴は人事発令が持ち、割当履歴テーブルは持たない
- 異動・在籍イベント(入社、異動、休職、復職、退職)を履歴として記録、閲覧する
- 採用の募集と候補者パイプライン(応募〜内定の段階遷移)を管理する(`recruitment:manage`。閲覧も人事に限定)
- 表彰を記録する(一覧は社内公開)。懲戒を記録する(hr 限定、web 画面なし)
- 人員計画(年度・部署別の計画人数)を記録し、実在籍数と比較する

## 申請ワークフロー

- 申請テンプレートの一覧と詳細を確認する
- テンプレートを指定して申請を提出する
- 自分宛の承認待ち一覧と、自分が出した申請を確認する
- 申請を承認または却下する(コメント付き)
- 全社の申請を横断で確認する(`application:read:all` を持つロール)
- テンプレートごとに、組織上の直属上司・部門責任者・上位管理職、IAM ロール、従業員指定を組み合わせた多段承認を定義する
- 申請内容と申請者属性による条件分岐、全員承認、必要人数、期限、期限後の承認者、却下または差戻しを設定する
- 差戻し後は監査履歴を残した新しいラウンドとして再申請する
- 期間とテンプレートを限定して代理承認を設定する
- 候補者不足で停止した承認フローへ、監査理由付きで承認候補者を再割り当てする

## 勤怠と休暇

- 出退勤を打刻し、自分の勤怠と月次サマリを確認する
- 上長はレポートライン配下の勤怠を閲覧する(スコープ権限。全社は `attendance:read:all` を持つロール)
- 休暇を申請し、残数を確認する
- 休暇を承認または却下する
- 上長はレポートライン配下の休暇申請と残数を閲覧する(スコープ権限)
- 一覧は scope=reports(配下全員)または scope=all(全社)で横断取得できる(目標・勤怠・休暇)
- 会社カレンダー(会社休日・振替出勤日)を管理する
- 勤務形態(フレックス・裁量労働などの区分)を期間つきで記録する。適法性判定はしない
- 時間外の参考集計を表示する(営業日×8時間を超えた分の単純集計。法定判定はしない)

## 経費

- 経費を申請し、自分の経費を確認する
- 自分宛の承認待ちを確認し、承認または却下する

## 稟議

- 承認者と金額を指定して稟議を起案する
- 自分宛の決裁待ちを確認し、承認または却下する(コメント任意、二重決定防止)
- 全社の稟議を横断で確認する(`ringi:read:all` を持つロール)

## 予算

- 部署と会計期間ごとの予算を登録し、金額やメモを修正する
- 予算の詳細で、承認済み経費による消化額と残額を確認する
- 会計期間を指定し、部署ごとの予算・消化額・残額を横断で確認する
- 予算は記録と集計の閲覧に閉じ、承認制御や自動締めのような制御は持たない

## 給与記録

- 給与改定の事実を履歴として記録、閲覧する(`salary_revision` 権限のみ。本人閲覧の例外なし)

## 取引先と契約

- 取引先を検索、登録、更新、アーカイブする(台帳は社内公開、管理は `partner:manage`)
- 取引先ごとの契約記録(契約日、期間、更新期限)を記録、閲覧する(閲覧は `contract:read:all`、記録は `contract:manage`)

## ナレッジ

- ナレッジを検索する(キーワード、カテゴリで絞り込み)
- ナレッジの詳細を確認する
- ナレッジを作成、編集、削除する

## アナウンスと規程・文書

- 社内アナウンスを作成、公開する(公開時に全従業員へ通知。`announcement:manage`)
- 規程集を版管理する(新版の連番自動採番、版履歴の閲覧。閲覧は全認証者)
- 文書台帳(契約書などの所在・期限のメタデータ)を記録する(`document:read:all` / `document:manage`)

## 規程・手続き(governance)

- YAML front matter 付き Markdown を同期し、版、施行日、適用対象、責任 role、参照を検索用に投影する
- 手続きの順序、担当、期限、確認、教育、証跡要求を Definition として構造化する。ProcedureCase の自動実行は行わない
- 文書版へ組織 role による公開 review を設定できる。現行 review は candidate snapshot と合議体 quorum を持たない
- 公開済みの対象文書を従業員が閲覧し、必要な文書は確認済み記録を残す
- 組織図の変更後に、未割当責任者、参照切れ、期限切れ、固定人名・部署名、authority rule の重複候補を検査する
- authority rule と control metadata は表示と検査の宣言であり、業務 API の強制や ControlRun の実施証明ではない

## 会議体と意思決定記録

- 会議体の一覧と詳細を確認する(閲覧は全認証者)
- 会議体を登録、更新、アーカイブする(`meeting:manage`)
- 会議体ごとの議事録を確認し、記録する(記録は全認証者、更新は作成者本人か `meeting:manage`)
- 会社の意思決定を ADR 形式(背景、決定、帰結)で確認する(閲覧は全認証者)
- 意思決定記録を作成、更新し、後続の記録で置き換える(`decision:manage`)

## 会議室と備品

- 会議室の空き状況を確認し、予約する
- 備品を登録し、貸出と返却を記録する
- 備品を廃棄済みにする(理由と日付を記録。貸出中は廃棄不可、廃棄済みは貸出不可)
- 現在貸出中の備品を保有者ごとに横断で確認する(管理者向け)
- 棚卸しを開始し、対象備品の現物確認(確認者と所在メモ)を記録して締める

## スキルと目標

- スキルの一覧を確認し、自分のスキルを登録または更新する
- 資格・免許のマスタと保有記録(取得日・有効期限)を管理する(自分の保有は本人閲覧可)
- 目標を作成し、自己評価、上長評価、最終評価を登録する
- 上長はレポートライン配下の目標を閲覧・評価する(スコープ権限。全社は `goal:read:all` / `goal:evaluate` を持つロール)
- 全社・部門・個人の目標をツリーで俯瞰する(全社・部門目標は社内公開、個人目標は閲覧スコープでフィルタ)

## 個別面談とアンケート

- 1on1の履歴を確認し、記録を作成する
- オープン中のアンケートに回答し、集計を確認する

## 感謝(サンクス)

- 同僚へ感謝メッセージを送る
- 自分の月次の贈与原資(残ポイント)と受け取った感謝を確認する
- 交換カタログの報酬一覧を確認し、ポイントと引き換えに交換を申請する
- 報酬カタログを登録、編集する(管理者)
- 交換申請の承認待ちを確認し、承認または却下する

## キャリア

- 自分のキャリアシートを確認し、更新する
- 社内公募の一覧を確認し、応募する

## オンボーディング

- オンボーディングのテンプレートを管理し、社員に割り当てる
- 入社と退職の人事発令に対応するテンプレートを設定し、冪等なバッチでタスクを自動展開する
- 自分のタスクを確認し、完了にする
- 閲覧担当者は社員別の進行状況を確認し、管理権限がない場合は割り当てやテンプレート変更を行わない

## 評価

- 評価サイクルを作成し、開始と締切を切り替える
- 評価フォームを提出し、結果を確認する
- サイクル開始時に組織図から自己、直属上司、同僚、部下の 360 度評価フォームを重複なく一括作成し、種別ごとの提出状況を集計する
- 評価結果を確定までは本人非公開にし、サイクル単位で一括開示する(`review:administer`)。閲覧はサイクル運営者、終了後の本人、組織上の上司に限る
- 等級割当に評価サイクルを紐づけて昇格の根拠を記録する

## シフト

- シフトパターンと割当を作成し、公開する
- シフト交代を申請し、申請当事者でない管理者が承認する

## 研修

- 研修コースを作成し、一覧と詳細を確認する
- 研修に登録し、受講を完了にする

## 通知

- 自分宛の通知と未読数を確認する
- 通知を既読にする(個別、一括)
- 宛先を指定して通知を送る(`notification:send` を持つロール)

## 労務・ライフイベント手続き

事実の記録と申出のワークフローのみを扱い、給付額や税額の計算、法的判定は持たない。

- 出張を申請し、自分の申請を確認、編集、取り消す
- 貸与品のレンタルを予約し、自分の予約を確認、編集、取り消す
- 退職を申し出て、受付から書類交付までの状況を記録する
- ライフイベント(結婚、出産、転居、忌引、扶養変更など)を届け出る
- 産休、育休、介護休業を申し出て、期限を管理する。給付計算と法的判定は行わない
- 在職、就労、退職などの証明書発行を依頼する
- 取引先の反社チェックを申請し、申請者本人ではない管理担当者が確認結果を記録する
- 全社の労務手続き(証明書・退職・ライフイベント・休業・出張・貸与品)を横断で確認する(`*:read:all` を持つロール)
- 申出の状態を代理で進める(証明書の発行、退職の受理、届の承認、貸与品の貸出・返却など。`*:manage` を持つロール)
- 健康診断・ストレスチェックの実施記録(実施日と受診状況のみ。結果は持たない)を管理する(hr 限定)
- 労災・事故の発生を記録し、対応完了を記録する

## 監査

- 重要操作と認可判断の監査イベントを検索し、詳細を確認する(`audit:read`)
- `audit:export` を持つ利用者は、指定した検索条件の監査イベントを書き出す

## 個人設定

- Web で表示テーマや表示言語を変更する。API、CLI、Schema には同期しない

## ダッシュボードとバッチ

- ダッシュボードの集計を表示する
- 経営ダッシュボードで在籍・入退社・打刻・申請滞留・目標達成率を俯瞰する(`management_dashboard:view`)
- バッチの状況を表示する
