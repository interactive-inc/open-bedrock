# System添付の開示

`GET /system/attachments/:attachmentId` は、預けたAccount本人に、未紐付けの添付内容を返す。Human、Agent、Service、Connectorのいずれも現在の認証状態を満たす必要がある。業務への紐付け後は、所有Appが親レコードの閲覧資格を検査する入口を使う。Systemはその業務資格を推定しない。

## 内容と資格の確定

本体の取得と復号には、最初に確認した同じ添付metadataを使う。復号結果のSHA-256と容量が一致しない場合は内容を返さない。

内容を返す前に、Accountの状態とtoken version、機械credentialの有効期間と失効、Connectorの状態を再検査する。同じtransactionで、添付の所有者、未紐付け状態、内容digest、表示metadata、保存先、暗号鍵、作成時刻が取得開始時と一致することを検査する。取得中の紐付け、消去、内容変更、認証失効を検出した場合は開示を拒否する。

最終検査と閲覧監査の保存は一つのD1 batchで確定する。監査の作成、保存、保存内容の照合または最終検査に失敗した場合は、閲覧監査を巻き戻し、内容を返さない。監査を保存できない場合は503、資格失効は401、添付の不一致は404を返す。

## 閲覧記録の意味

`attachment.read` は、Account、認可方針、token version、機械credentialの識別子、対象添付、内容digest、容量、確定時刻を残す。鍵、tokenそのもの、保存先は監査へ記録しない。

この記録はサーバーが内容の開示を許可した事実である。相手への配信成功、人間が内容を読んだ事実、作業の成果確認、承認、責任の引継ぎを証明しない。通信切断後の再取得は別の閲覧として記録する。

この入口は所有者本人の未紐付け添付に限る。目的別・項目別の添付開示設定や業務Appの閲覧資格を、この入口の検査だけで保証しない。[保持と削除停止](system-attachment-preservation.md)は別の制約である。

## 業務に紐付いた添付

所有Appは親レコードの現在の閲覧資格を検査する。Systemは、署名・issuer・audienceの検証が済んだBearerの発行元、Account、技術的権限、期限をtransaction内で再照合する検査を提供する。機械credentialは所属するPrincipalとConnectorの状態を要求し、外部IdPの認証は確認したIdentityBindingへの対応と未取消を要求する。業務資格をこの技術的検査だけで補わない。

領収書の取得では、現在のSystem権限から経費閲覧資格を解決し直し、Companyの本人対応・在籍・会社資格、経費・案件・判断候補・委任、添付の内容と鍵を固定する。期限到達、案件の取消、閲覧資格の失効、内容の差し替えを、閲覧監査の保存前後に同じtransactionで検出する。古いsessionが持つ権限で全件閲覧を許可しない。

認可条件の変更は403、確認した添付の変更は422、閲覧監査の保存失敗は500を返し、添付内容を返さない。失敗したtransactionには成功の閲覧監査を残さない。監査は認証元の識別子、経費、内容digest、容量を記録し、token、復号鍵、保存先を含めない。
